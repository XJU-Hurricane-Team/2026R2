# 2026R2 上位机接口说明文档

## 1. 概述

本文档描述上位机通过 micro-ROS 与下位机通信的当前接口。内容以 `User/Application/Src/microros_ctrl.c` 及其直接调用的控制代码为准。

- ROS 2 节点名：`board`
- 节点命名空间：空
- 控制服务：`/control_dispatch_srv`
- 导航速度输入：`/nav_speed_heading_data`
- 动作状态输出：`/control_dispatch_topic`
- 导航状态输出：`/nav_topic`

> 注意：服务响应仅表示下位机已经接收并分派请求，不表示动作已经执行完成。异步动作完成状态应通过动作状态输出话题判断。

---

## 2. 控制调度服务

###  服务定义

- 服务名：`/control_dispatch_srv`
- 服务类型：`custom_msg/srv/ControlDispatch`

请求结构：

```text
int8 command_mode
int8 event
geometry_msgs/Point point
bool is_return
```

响应结构：

```text
bool success
string message
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `event` | 模块选择：`0` 夹爪、`1` 机械臂、`2` 抬升/台阶 |
| `command_mode` | 所选模块的动作编号，具体含义见下文 |
| `point` | 机械臂动态抓取目标点，仅 `event=1, command_mode=5` 使用 |
| `is_return` | 该动作指令完成后是否需要向上位机反馈。 |
| `success` | 当前对所有请求固定返回 `true`，包括未知的 `event` 或 `command_mode` |
| `message` | 当前未赋值，暂时无用 |

## 3. 夹爪模块（event = 0）

| `command_mode` | 状态 | 下位机行为 |
| ---: | --- | --- |
| 0 | INIT | `catch_set_state(CATCH_STATE_INIT)`，夹爪初始化 |
| 1 | READY | `catch_set_state(CATCH_STATE_READY)`，进入准备状态 |
| 2 | RECOGNIZE | `catch_set_state(CATCH_STATE_RECOGNIZE)`，启动识别流程 |
| 3 | CHECK | `catch_set_state(CATCH_STATE_CHECK)`，检查抓取状态 |
| 4 | DONE | `catch_set_state(CATCH_STATE_DONE)`，进入完成状态 |

当前代码中的典型流程为：

```text
INIT(0) -> READY(1) -> RECOGNIZE(2) -> CHECK(3) -> DONE(4)
```

补充说明：

- 进入 INIT、READY 或 DONE 并处理完成后，通常在 `/control_dispatch_topic` 发布 `1`。
- RECOGNIZE 检测到目标后，会在 `/nav_topic` 发布 `0`，随后夹爪内部转入抓取状态。
- CHECK 当前直接在 `/control_dispatch_topic` 发布 `1`；原有距离检测判定代码处于注释状态。

## 4. 机械臂模块（event = 1）

收到任一机械臂命令时，固件首先设置 `arm_return_enabel = true`。

| `command_mode` | 功能 | 下位机行为 |
| ---: | --- | --- |
| 0 | 初始化 | 设置机械臂状态索引 0 |
| 1 | 向上抓取准备 | 状态索引 1，并记录本次动态抓取类型 |
| 2 | 向下抓取准备 | 状态索引 2，并记录本次动态抓取类型 |
| 3 | 40 cm 向上抓取准备 | 状态索引 3，并记录本次动态抓取类型 |
| 4 | 平地抓取准备 | 状态索引 4，并记录本次动态抓取类型 |
| 5 | 动态抓取 | 根据最近一次 1～4 的准备命令写入 `point` 目标，然后设置状态索引 5 |
| 6 | 放置 | 设置状态索引 6 |
| 7 | 准备取出 | 设置状态索引 7 |
| 8 | 放置第 2 层 | 设置状态索引 8 |
| 9 | 放置第 3 层 | 设置状态索引 9 |
| 10 | 摄像头识别位 | 设置状态索引 10 |
| 11 | 关闭气泵 | 设置状态索引 11 |
| 12 | 放置完成后返回 | 启动放置返回序列，返回状态索引为 1 |

### 4.1 动态抓取（command_mode = 5）

动态抓取必须先发送准备命令 1、2、3 或 4，再发送命令 5。命令 5 根据最近一次准备类型调用不同的目标设置函数：

| 前一条准备命令 | 动态目标函数 |
| ---: | --- |
| 1 | `robot_arm_set_dynamic_catch_target_up(x, y, z)` |
| 2 | `robot_arm_set_dynamic_catch_target_down(x, y, z)` |
| 3 | `robot_arm_set_dynamic_catch_target_up2(x, y, z)` |
| 4 | `robot_arm_set_dynamic_catch_target_down2(x, y, z)` |

如果没有先发送 1～4，命令 5 仍会启动状态索引 5，但不会更新动态目标坐标。因此上位机必须保证命令顺序正确。

示例流程：

```text
向上动态抓取：command_mode=1 -> command_mode=5（携带 point）
向下动态抓取：command_mode=2 -> command_mode=5（携带 point）
```

机械臂动作完成时，当前机械臂状态机通常在 `/control_dispatch_topic` 发布 `2`。

## 5. 抬升与台阶模块（event = 2）

| `command_mode` | 功能 | 下位机行为 |
| ---: | --- | --- |
| 0 | 上台阶 | `lift_set_stair_mode(1)` |
| 1 | 下台阶 | `lift_set_stair_mode(2)` |
| 2 | 启动底盘接近开关检测 | `chassis_proximity_switch()`；检测到任一接近开关后在 `/nav_topic` 发布 `0` |
| 3 | 抬升复位 | `lift_set_target(0.0f)` |
| 4 | 自动抬升至坡道目标 | `auto_lift_set_target(LIFT_TARGET_UP_RAMP_DEG)`；到位后在 `/control_dispatch_topic` 发布 `1` |
| 5 | 抬升至 R1 目标 | `lift_set_target(-LIFT_TARGET_UP_R1_DEG)`，并设置 `up_R1_flag=true` |
| 6 | 仅使用 VL53L1 触发 | 设置 `only_vl53l1_flag=true`，影响后续抬升触发判定 |

注意事项：

- 命令 3 和 5 使用普通目标设置接口，服务回调本身不会等待到位。
- 命令 6 只设置模式标志，不会单独启动抬升动作。
- 台阶动作执行期间，遥控侧除急停键外的其他抬升按键会被忽略。
- 旧文档中的 `/stair_topic` 已不在当前 `microros_ctrl.c` 中创建；当前固件使用 `/nav_topic` 和 `/control_dispatch_topic` 反馈相关状态。

## 6. 导航接口

### 6.1 导航速度输入

- 主题：`/nav_speed_heading_data`
- 类型：`custom_msg/msg/SpeedHeading`
- QoS：Best Effort
- 方向：上位机发布，下位机订阅

```text
float32 linear_x
float32 linear_y
float32 angular_z
```

约定单位：

| 字段 | 单位 | 说明 |
| --- | --- | --- |
| `linear_x` | m/s | X 方向线速度 |
| `linear_y` | m/s | Y 方向线速度 |
| `angular_z` | rad/s | Z 轴角速度 |

收到新消息后，下位机更新全局导航速度参数 `nav_sub_pram`；LED3 最多每 500 ms 翻转一次，用于指示消息接收活动。

### 6.2 导航状态输出

- 主题：`/nav_topic`
- 类型：`std_msgs/msg/Int8`
- 方向：下位机发布，上位机订阅

当前调用语义：

| 值 | 含义 |
| ---: | --- |
| 0 | 导航停止请求 |
| 1 | 导航启动请求 |

该请求主要用于固定直线移动部分，如抓取矛头，上下台阶等，不用于跑点。

## 7. 动作状态反馈

- 主题：`/control_dispatch_topic`
- 类型：`std_msgs/msg/Int8`
- 方向：下位机发布，上位机订阅

当前代码使用的状态值：

| 值 | 当前来源与含义 |
| ---: | --- |
| 1 | 夹爪动作完成、抬升自动目标到位或其他抬升流程完成 |
| 2 | 机械臂状态机动作完成 |

该消息没有携带原始请求 ID，也不区分同一模块内的具体命令。上位机一般串行下发需要等待完成的动作，并结合自身当前流程解释反馈值。这部分属于状态反馈机制设计的失败，反馈太过简单。

## 8. 日志主题

代码中定义了以下发布接口：

| 主题 | 类型 | 数据格式 |
| --- | --- | --- |
| `/log/msg` | `std_msgs/msg/String` | 文本日志 |
| `/log/data` | `std_msgs/msg/Float32MultiArray` | 第 0 个元素为数据 类型ID，后续元素为数据值 |
